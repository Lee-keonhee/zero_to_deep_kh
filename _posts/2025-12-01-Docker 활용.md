# 가상환경과 도커 개요

## 가상화의 개념과 도커의 등장 배경

![](../assets/img/posts/2025-12-01-Docker%20활용-20251202102042.png)
### 가상화의 개념

- **정의**
    - 하나의 물리적 자원을 여러 개의 논리적 자원으로 나누거나, 반대로 여러 자원을 하나처럼 묶어 사용하는 기술
        
        → CPU, 메모리, 저장공간, 네트워크 등 하드웨어 자원을 추상화하여 효율적으로 활용 가능
        
- **핵심 아이디어**
    - "추상화(Abstraction)"와 "격리(Isolation)"
    - 서로 다른 애플리케이션이나 운영체제를 하나의 물리 서버 위에서 독립적으로 실행 가능
    - 하나의 실물 컴퓨팅 자원을 마치 여러 개인 것처럼 가상으로 쪼개서 사용
- **종류**
    - 서버 가상화: VMware ESXi, Hyper-V, KVM 등 하이퍼바이저 기반
    - 스토리지 가상화: SAN, NAS 등
    - 네트워크 가상화: SDN(Software Defined Network)

### 가상화의 역사

- **1960년대**
    - IBM 메인프레임에서 VM(가상 머신) 개념 등장. (예: IBM CP-40, CP-67)
    - 여러 사용자가 동시에 하나의 메인프레임을 나눠 쓰기 위해 필요했음.
- **1990년대**
    - 서버 가상화 본격화.
    - VMware가 1999년에 x86 기반 가상화 소프트웨어 출시 → 범용 서버에서도 가상화 가능해짐.
- **2000년대**
    - 기업 IT 인프라에서 데이터센터 통합(서버 자원 효율화)에 필수 기술로 자리잡음.
    - Xen, KVM 등 가상화 관리 오픈소스 하이퍼바이저 등장.
    - 클라우드 서비스(AWS, Azure, GCP)의 기반 기술로 발전.
- **2010년대**
    - "가상머신은 무겁고 느리다"는 문제의식 → 경량화된 컨테이너(Container) 방식 확산.
    - Linux에서 cgroups(Control Groups), namespace 기능이 커널에 탑재되면서 LXC(Linux Containers) 가능해짐.

### 도커(Docker)의 등장 배경

- **기존 가상머신의 한계**
    - 기존 가상머신(VM)은 하드웨어 자원을 분리하여 독립적인 OS를 구축하여 활용
    - VM은 하이퍼바이저 위에 OS 전체를 올려야 해서 부팅이 느리고 자원 소모가 큼
- **컨테이너의 장점**
    - OS 수준에서 커널을 공유하면서 프로세스를 격리해 실행 → 훨씬 가볍고 빠름.
    - 모든 종속성이 이미지에 포함되어 있어 환경에 관계없이 일관되게 실행될 수 있음 → 높은 이식성
- **컨테이너 엔진 도커 (2013년, dotCloud에서 오픈소스 공개)**
    - LXC 기반 컨테이너 기술을 개발자 친화적 툴체인으로 패키징.
    - 이미지(Image), 컨테이너(Container), 레지스트리(Registry) 개념 정립.
    - DevOps, CI/CD, 마이크로서비스 아키텍처 확산의 촉매제가 됨.

### 컨테이너와 가상 머신(VM) 비교
![](../assets/img/posts/2025-12-01-Docker%20활용-20251202103355.png)
- **가상 머신(VM)**
    
    - 하나의 물리적 호스트에서 여러 개의 가상 머신을 생성하고 관리할 수 있도록 해주는 기술.
    - 가상화 계층을 구현해주는 소프트웨어인 '하이퍼바이저(Hypervisor)' 기술을 활용
    - Windows/Linux 등 다양한 선택 가능하지만 초기 부팅 시간이 길고, 설치 용량이 GB 단위로 큼
    - 각 머신마다 완전한 운영체제 (Guest OS)가 존재하여 무겁고, Host 컴퓨터에 많은 부하를 줌
    - 예: 각 VM마다 별도 Ubuntu OS 설치.
- **컨테이너**
    
    - Host의 운영체제(OS) 위에서 실행되며 운영체제의 소프트웨어를 공유.
        - 일반적으로 Linux 환경에서 작동하며 초기화 시간이 짧고, MB 단위의 용량이 요구됨
    - 가상 머신보다 가볍고 빠르며, 여러 개의 컨테이너를 하나의 시스템에서 독립적으로 실행 가능.
    - 예: Ubuntu 컨테이너는 OS 전체가 아닌 필요한 라이브러리만 포함.
- **비교 표**
    
    |항목|가상 머신(VM)|컨테이너|
    |---|---|---|
    |크기|크고 무거움 (GB 단위)|작고 가벼움 (MB 단위)|
    |시작 시간|느림 (분 단위)|빠름 (초 단위)|
    |자원 사용|많음 (별도 OS 포함)|적음 (커널 공유)|
    |이식성|하이퍼바이저 의존|높은 이식성|
    |격리 수준|완전 격리 (OS 포함)|프로세스 수준 격리|
    

## Docker 개요

### Docker란?

- Docker는 애플리케이션과 실행에 필요한 종속성(코드, 런타임, 라이브러리, 설정)을 컨테이너라는 경량화된 환경에 패키징하여 실행, 배포, 관리하는 오픈소스 플랫폼
- 컨테이너는 호스트 OS의 커널을 공유하여 자원을 효율적으로 사용
- 2013년 도입, 마이크로서비스, DevOps, 클라우드 환경에서 널리 사용
- 핵심 원칙: "Build, Ship, and Run Any App Anywhere"
    - Build: 개발 환경에서 애플리케이션 패키징.
    - Ship: 이미지를 레지스트리에 공유/배포.
    - Run: 로컬, 서버, 클라우드 등 모든 환경에서 동일 실행

### Docker의 주요 구성 요소

- **Docker 엔진**
    - 컨테이너를 생성, 관리, 실행하는 핵심 런타임.
    - 클라이언트-서버 아키텍처
        - `docker` : 사용자가 직접 터미널에 입력하는 명령줄 인터페이스(CLI) 클라이언트 명령어
        - `dockerd` : 백그라운드에서 지속적으로 실행되는 서버 프로세스인 **도커 데몬(Docker Daemon)**을 실행하는 명령어
    - 도커 데몬은 백그라운드에서 이미지 빌드, 컨테이너 생성/실행/중지/제거, 네트워크 및 볼륨 관리, 컨테이너의 상태 모니터링 등 모든 핵심 작업을 담당
- **이미지**
    - 컨테이너를 생성하기 위한 정적인 읽기 전용 템플릿 또는 설계도
    - 애플리케이션을 실행하는 데 필요한 모든 것(코드, 런타임, 시스템 도구, 라이브러리, 환경 설정 등)을 포함하고 있는 파일 묶음
    - 이미지는 여러 개의 읽기 전용 레이어(Layer)로 구성되며, 변경 사항이 발생하면 해당 레이어만 새로 추가되어 효율적인 용량 관리와 빠른 빌드가 가능
- **컨테이너**
    - 이미지 템플릿을 기반으로 실제로 구동되는 실행 환경
        - 이미지가 클래스라면, 컨테이너는 인스턴스.
    - 호스트 운영체제(OS)의 커널을 공유하면서도 독립된 환경에서 애플리케이션이 작동하도록 공간 격리
    - 컨테이너는 격리되어 있기 때문에, 한 컨테이너에서 문제가 발생하거나 환경이 바뀌더라도 다른 컨테이너나 호스트 시스템에 영향을 주지 않음
- **레지스트리**
    - 도커 이미지를 저장하고 공유하는 중앙 집중식 저장소
    - 이미지를 안전하게 보관하고 전 세계의 사용자나 서버로 배포하는 역할
    - 예: Docker Hub, AWS ECR, Google Artifact Registry
- **Docker CLI**
    - `docker run`, `docker build`, `docker pull` 등 사용자가 도커를 사용하기 위한 명령어
- **Docker Desktop**
    - 도커를 GUI 환경에서 실행 시키는데 도움을 주는 툴
        - [윈도우 설치](https://www.codeit.kr/tutorials/188/Docker%20%EC%84%A4%EC%B9%98%ED%95%98%EA%B8%B0\(Windows\)) 코드잇 자료
        - [맥 설치](https://www.codeit.kr/tutorials/189/Docker%20%EC%84%A4%EC%B9%98%ED%95%98%EA%B8%B0\(macOS\)) 코드잇 자료
    - 리눅스가 아닌 윈도우나 맥OS 등 GUI 환경이 사용되는 운영체제에서 활용하기 편함
    - 도커 데스크톱 실행 시 터미널에서 도커 CLI 활용 가능

### Docker의 사용 사례

- **개발 환경 통합**: 개발, 테스트, 프로덕션 환경에서 동일한 실행 환경 제공.
- **마이크로서비스**: 애플리케이션을 독립된 서비스 단위로 분리, 배포.
- **CI/CD 파이프라인**: 빌드, 테스트, 배포 자동화 지원(예: Jenkins, GitHub Actions).
- **클라우드 배포**: AWS, Azure, GCP 등 클라우드 환경에서 이식성 제공.
- **테스트 환경**: 격리된 환경에서 테스트 실행, 빠른 환경 구성/폐기.

### Docker의 이점

- **이식성**: 동일한 이미지를 모든 환경에서 실행 가능.
- **효율성**: 경량화된 컨테이너로 자원 사용 최소화.
- **확장성**: 마이크로서비스 아키텍처와 오케스트레이션 도구(Kubernetes, Swarm) 통합.
- **일관성**: 개발부터 프로덕션까지 동일 환경 보장.
- **생산성**: 빠른 배포와 테스트로 개발 주기 단축.

### Docker의 최신 트렌드

- **라이선스 변경**: Docker Desktop(2021년 이후) 무료 사용 제한, 기업 대상 유료화.
- **대체 기술**: Podman, containerd 등 루트리스 컨테이너 도구 등장.
- **오케스트레이션**: Kubernetes와의 통합으로 대규모 배포 지원.
- **보안 강화**: 이미지 스캔, 최소 권한 원칙 강조.

