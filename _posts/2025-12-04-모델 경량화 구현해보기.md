# 플랫폼 별 모델 경량화

### **구현 양자화 플랫폼**
- TF-Lite
	- 모바일 및 엣지 장치를 위한 TF의 경량 버전, tensorflow 모델에서 쉽게 양자화 가능
	- 동적 범위 양자화, 전체 정수 양자화, float16 양자화, 양자화 미세조정 등을 지원
- Torch ao
	- pytorch의 고급 최적화 라이브러리의 일부, 파이토치 모델을 여러 방식으로 양자화
	- FX/ pt2e 워크 플로우를 통해 PTQ,QAT, 동적, 가중치 전용(woq) 양자화 등을 지원
- ONNX
	- 프레임워크 간 모델 교환을 위한 표준 포맷
	- 다양한 런타임, 하드웨어로 손쉬운 배포
	- onnxruntime-quantization으로 정적(QDQ/QLinear), 동적 양자화 및 float16 다운캐스트 지원


## **TensorFlow(Keras) 모델 경량화  **

TensorFlow 자체로 개발한 Keras 모델은 TensorFlow에서 제공하는 TF-Lite 플랫폼으로 변환을 통해 양자화가 가능합니다.


### **모델 생성  **
	먼저 간단한 이미지 분류 케라스 모델을 생성합니다.
```python
import tensorflow as tf
from tensorflow.keras import layers

# MobileNetV3Small 모델 활용  
base_model = tf.keras.applications.MobileNetV3Small(input_shape=(img_height,img_width,3),  
                                                    include_top=False,  
                                                    weights='imagenet')  
  
  
global_pooling = layers.GlobalMaxPooling2D() #(3)  
bn = layers.BatchNormalization()  
dr = layers.Dropout(0.3)  
classifier = layers.Dense(4)  
softmax = layers.Softmax()  
  
inp = tf.keras.Input((img_height,img_width,3))  
# x = rescale(inp)  
x = base_model(inp)  
x = global_pooling(x)  
x = bn(x)  
x = dr(x)  
x = classifier(x)  
out = softmax(x)  
model = tf.keras.Model(inp, out, name = 'MobileNet')  
  
model.compile(optimizer=tf.keras.optimizers.Adam(learning_rate=0.0005),  
              loss=tf.keras.losses.SparseCategoricalCrossentropy(),  
              metrics=['accuracy'])  
  
checkpoint_path = "./checkpoint_tf/model.weights.h5"  
cp_callback = tf.keras.callbacks.ModelCheckpoint(filepath=checkpoint_path,  
                                                 save_weights_only=True,  
                                                 save_best_only = True,  
                                                 verbose=1)  
model.summary()  
history = model.fit(train_dataset, epochs=5, validation_data = val_ds, callbacks=[cp_callback])

```

### **모델 저장**  
텐서플로우는 크게 3가지의 파일 형식으로 모델을 저장합니다.  
  
- `.h5` : 모델의 가중치와 모델 구조를 저장하는 데 사용되는 HDF5 형식, 레거시 형식으로 간주되지만 여전히 널리 사용  
- `.keras` : 모델의 구조, 가중치, 훈련 구성(optimizer, loss 등)을 포함하며 HDF5보다 더 유연하고 확장 가능한 형식  
- `.pb`: SavedModel 형식으로, 모델의 그래프와 가중치를 포함하며 TensorFlow Serving, TFLite, TensorFlow.js 등 다양한 환경에서 모델을 배포하고 실행하는 데 사용되는 표준 형식

해당 과정에서는 단순히 TensorFlow 모델로 저장


## 텐서 라이트 경량화

텐서플로우 프레임워크로 구성되는 케라스 모델은 대표 경량화 플랫폼인 TF-Lite와의 연동성이 좋습니다.  텐서플로우의 `lite` 모듈을 활용하면 케라스 모델을 쉽게 TF-Lite 모델로 양자화 변환이 가능합니다.  
  
- lite 모듈의 `TFLiteConverter` 객체를 통해 기존 모델을 변환기에 탑재  
- `convert()` 함수를 통해 변환시작, 기본 변환시 양자화 없이 플랫폼만 변환

```python
import tensorflow as tf  
from tensorflow import lite  
from google.colab import files  
  
# 저장된 모델 로드  
model = tf.keras.models.load_model(f'{m_path}/{name}.keras')  
  
# 케라스 모델로 부터 TF-Lite 모델로 변환  
converter = lite.TFLiteConverter.from_keras_model(model)  
  
# 양자화 없이 모델 변환  
tflite_model = converter.convert()  
  
# .tflite 파일로 저장  
with open(f'{m_path}/{name}.tflite', 'wb') as f:  
    f.write(tflite_model)
```

### 동적 양자화 적용  
  
TF-Lite는 기본적으로 <u>동적 양자화 변환</u>을 지원합니다.  
  
- TF-Lite 변환 시 가중치가 8비트 정수로 양자화 되는 기본 옵션 `Optimize.DEFAULT `설정  
- 양자화된 모델을 사용할땐, 부동 소수로 역 양자화 하여 연산 (입력은 float)- 양자화 되는 가중치의 타입을 `supported_types` 옵션으로 조정 가능

```python
import tensorflow as tf  
from tensorflow import lite  
from google.colab import files  
  
# 저장된 모델 로드  
model = tf.keras.models.load_model(f'{m_path}/{name}.keras')  
  
# 케라스 모델로 부터 TF-Lite 모델로 변환  
converter = lite.TFLiteConverter.from_keras_model(model)  
  
# 양자화 없이 모델 변환  
tflite_model = converter.convert()  
  
# .tflite 파일로 저장  
with open(f'{m_path}/{name}.tflite', 'wb') as f:  
    f.write(tflite_model)
```
#### 동적 양자화 적용  
  
TF-Lite는 기본적으로 동적 양자화 변환을 지원합니다.  
  
- TF-Lite 변환 시 가중치가 8비트 정수로 양자화 되는 기본 옵션 `Optimize.DEFAULT `설정  
- 양자화된 모델을 사용할땐, 부동 소수로 역 양자화 하여 연산 (입력은 float)  
- 양자화 되는 가중치의 타입을 `supported_types` 옵션으로 조정 가능

```python
model = tf.keras.models.load_model(f'{m_path}/{name}.keras')  
converter = tf.lite.TFLiteConverter.from_keras_model(model)  
  
# 기본 학습후 동적 양자화  
converter.optimizations = [tf.lite.Optimize.DEFAULT]  
# 양자화 타입 변경  
# converter.target_spec.supported_types = [tf.float16]  
  
# 모델 변환  
tflite_model = converter.convert()  
  
# Save the model.  
with open(f'{m_path}/{name}_dq.tflite', 'wb') as f:  
    f.write(tflite_model)
```

#### 정적 양자화 적용  
  
정적 양자화를 위해선 Calibration(보정)을 위한 데이터세트가 필요합니다.  
  
- 활성화 값까지 전부 양자화를 진행하기 위해서는 실제 데이터가 입력됬을때의 범위를 보정  
- 보정을 위한 대표 데이터 세트를 `representative_dataset` 에 입력


```python
# 보정을 위한 데이터세트 제공 함수  
def representative_dataset():  
    # 모델의 입력 레이어 이름  
    input_name = model.inputs[0].name  
    for data in val_ds.take(10):  
        # 입력 레이어 이름과 이미지 데이터를 매핑하는 딕셔너리 형태로 yield.        yield {input_name: data[0]}  
  
  
model = tf.keras.models.load_model(f'{m_path}/{name}.keras')  
  
converter = tf.lite.TFLiteConverter.from_keras_model(model)  
converter.optimizations = [tf.lite.Optimize.DEFAULT]  
  
# 데이터세트 제공 함수를 입력  
converter.representative_dataset = representative_dataset  
  
# # 입출력의 타입까지 INT8로 고정  
# converter.target_spec.supported_ops = [tf.lite.OpsSet.TFLITE_BUILTINS_INT8]  
# converter.inference_input_type  = tf.int8  
# converter.inference_output_type = tf.int8  
  
# 연산자 옵션 (최신 모델에서 활용)  
converter.target_spec.supported_ops = [  
    tf.lite.OpsSet.TFLITE_BUILTINS, # enable LiteRT ops.  
    tf.lite.OpsSet.SELECT_TF_OPS    # enable TensorFlow ops.  
]  
  
# 최신 변환 로직과 최적화 기법을 적용 (최신 모델에서 활용)  
converter.experimental_new_converter = True  
  
tflite_quant_model = converter.convert()  
  
with open(f'{m_path}/{name}_sq.tflite', 'wb') as f:  
    f.write(tflite_quant_model)
```

## 파이토치 모델 경량화  
  
파이토치 모델은 내부적으로 양자화 가능한 `torch ao` 모듈을 활용하거나, `ONNX` 플랫폼을 활용하여 양자화 가능합니다.  
  
- `torch ao`: PyTorch의 공식 양자화 API 및 기능 모음으로, 주로 PyTorch 환경 내에서 모델을 학습, 변환, 실행하는 데 사용  
  
- `onnx`: 서로 다른 딥러닝 프레임워크 간에 모델을 이동시킬 수 있도록 설계된 개방형 표준 포맷으로 양자화 변환을 지원

### 모델 생성  
  
파이토치를 활용하여 간단한 이미지 분류 모델이 존재한다고 가정하자.


#### 동적 양자화 (Eager Mode)  
동적 양자화는 Eager Mode Quantization 방식을 적용하여 간단하게 구현 가능하지만, 주로 일반 nn.Linear 모듈에만 호환이 되므로 CNN 구조의 모델에서는 효율성이 떨어집니다.

```python
from torch.ao.quantization import quantize_dynamic  
from torch import nn  
import time  
  
model.to('cpu')  
  
qmodel = quantize_dynamic(  
    model,  
    {nn.Linear, nn.Conv2d},        # 동적 양자화는 주로 선형레이어에만 적용  
    dtype=torch.qint8              # 가중치 int8, 활성은 런타임에 동적 스케일링 
)                                  # qint는 양자화 시에만 사용
print(qmodel)      # nn.quantized.dynamic.Linear 로 바뀐 것 확인
```
> Conv2dNormActivation 과 같은 복합 모듈은 양자화 적용이 안됨


#### 동적 양자화 (torchao)  
  
torchao 모듈의 quantize_ 함수를 활용하여 가중치를 직접 동적 양자화가 가능합니다. 해당 방법 또한 기본 토치 모듈에만 적용이 되므로 복합 모듈를 가진 구조에서는 효율성이 떨어집니다.

```python
from torchao.quantization import quantize_, Int8DynamicActivationInt8WeightConfig  
import copy  
  
model_dq = copy.deepcopy(model)  
quantize_(model_dq, Int8DynamicActivationInt8WeightConfig())  
print(model_dq)
```
> Linear 모듈의 weight가 LinearActivationQuantizedTensor로 변환

#### 정적 양자화 (FX Graph)  
FX Graph Mode Quantization 방식을 활용하면 추적을 통한 그래프를 생성해 컨볼루션, 활성화 모듈 및 여려 모듈이 합쳐진 복합 모듈도 파악해 양자화가 가능합니다.  
  
이때 정적 양자화를 위해선 켈리브레이션 과정을 추가합니다.  
  
    백엔드 엔진 설정 -> QConfig(양자화 옵션) 설정 -> prepare_fx (양자화 준비)  
    -> 캘리브레이션 (관측기를 통해 범위 측정) -> convert_fx (최종 양자 변환)


```python
import torch, torchvision  
from torch.ao.quantization import QConfigMapping, get_default_qconfig  
from torch.ao.quantization.quantize_fx import prepare_fx, convert_fx  
  
model.to('cpu').eval()  
  
# 백엔진 설정 (x86/서버면 x86, 모바일/ARM이면 qnnpack)torch.backends.quantized.engine = "x86"  
  
example = torch.randn(1, 3, 224, 224)  
  
# QConfig (전역 동일하게 주는 게 안전)  
qconfig = get_default_qconfig(torch.backends.quantized.engine)  
qmap = QConfigMapping().set_global(qconfig)  
  
# 준비(관측기 삽입 + 모듈 융합 + 추적 그래프 생성)  
prepared = prepare_fx(model, qmap, example)  
  
# 캘리브레이션 (대표 데이터 몇 배치 통과)  
with torch.inference_mode():  
    for i in range(2):  
        for images, labels in val_loader:  
            outputs = prepared(images)  
  
# 변환  
fx_model = convert_fx(prepared)  
print(fx_model)
```
> 복합 모듈 또한 양자화가 된것을 확인
> 하지만, 모바일넷과 같이 복잡한 연산(Depthwise Conv, ReLU6)을 포함하는 모델은 FX Graph 방식에서도 성능저하가 크게 일어날 수 있습니다.


#### 정적 양자화 (PT2E)  
torchao 모듈에 있는 pt2e는 pytorch의 내보내기 기반으로 양자화를 수행하는 방법으로 최근에 활발하게 개발이 되고있어, 복합 모듈과 복잡한 연산에서의 성능도 보장합니다.  
  
기존 FX에서 그래프 추적 방식과는 다르게 Python 바이트코드 레벨에서 분석하여 구조를 파악하여, 더 복잡한 Python 제어 흐름을 효과적으로 처리할 수 있게 해줍니다.  
  
pt2e는 대표적으로 X86, XNNPACK, XPU, OpenVINO 등의 백엔드 엔진을 사용합니다.
> XNNPACK을 사용하기 위해선 executorch 모듈이 설치되어있어야 합니다. XNNPACK은 모바일넷과 같이 복잡한 CNN 구조에 최적화 되어있습니다.

torch.export 모델(ExportedProgram) 생성 -> 백엔드 준비 -> prepare_pt2e (양자화 준비)  
-> 캘리브레이션 -> convert_pt2e (최종 양자화)

```python
from torchao.quantization.pt2e.quantize_pt2e import prepare_pt2e, convert_pt2e  
from executorch.backends.xnnpack.quantizer.xnnpack_quantizer import (  
  get_symmetric_quantization_config,  
  XNNPACKQuantizer,  
)  
from torch.export import Dim  
  
  
model = torch.load(f'{m_path}/{name}.pt', weights_only=False)  
  
model.to('cpu').eval()  
  
# 동적배치 처리시 더미 입력 배치가 2이상  
example_input = torch.randn(2, 3, 224, 224, device='cpu')  
  
# export (ExportedProgram는 일반 GraphModule에 비해 많은 정보를 담음)  
  
dynamic_shapes = {"x": {0: Dim("batch")}} # 동적 배치 처리  
export_model = torch.export.export(model, (example_input,),  
                                   dynamic_shapes=dynamic_shapes,  
                                   strict=True # 엄격 모드 활성화(TorchDynamo)  
                                   ).module()  
  
# 양자화를 위한 백엔드 준비  
# depthwise 아키텍처에서는 per-channel 옵션을 활성화 하여 qconfig 세팅  
qconfig = get_symmetric_quantization_config(  
    is_per_channel=True,  # 가중치 per-channel quantization)  
quantizer = XNNPACKQuantizer().set_global(qconfig)  
  
# export 모델과 백엔드를 입력하여 양자화 준비  
pt2e_model = prepare_pt2e(export_model, quantizer)  
  
print('prepare => calibration')  
# 캘리브레이션 (대표 데이터 몇 배치 통과)  
with torch.inference_mode():  
    for i in range(2):  
        for images, labels in val_loader:  
            outputs = pt2e_model(images)  
  
# 최종 양자화 변환  
pt2e_model = convert_pt2e(pt2e_model)
```

> Depthwise Convolution은 각 채널의 가중치(필터)가 독립적으로 학습되므로, 채널별로 범위을 책정하는 양자화 방식을 적용
> 실제 pt2e는 양자화를 위한 제로포인트와 스케일을 구축하지만, 기존 가중치 타입은 Float32 타입으로 유지하고 실제 런타임에서 양자화를 수행합니다.


### ExecuTorch 내보내기  
  
`torch ao` 의 pt2e 양자화는 다양한 최신 아키텍처 모델에서도 양자화가 잘 진행되지만, 실질적으로 INT8 타입등으로 바뀐 가중치를 가지지 않습니다.  
  
ExecuTorch는 모바일 및 엣지 등의 장치에서 토치모델의 온디바이스 배포를 위한 런타임 라이브러리로, pt2e 모델을 직접 양자화 하여 저장하고 런타임을 구성할 수 있습니다.  
  
- `torch.export`로 내보내진 모델을 [다양한 백엔드](https://docs.pytorch.org/executorch/stable/backends-overview.html) 설정과 함께 `.pte` 파일로 변환  
- pt2e로 양자화 정보를 가진 모델은 변환시 가중치가 양자화 되어 INT8등의 양자 타입으로 저장

```python

from executorch.backends.xnnpack.partition.xnnpack_partitioner import XnnpackPartitioner  
from executorch.exir import to_edge_transform_and_lower  
from torch.export import Dim, export  
  
# 동적 배치를 위한 예시 입력은 2개 이상 샘플로  
inputs = (torch.randn(2,3,224,224),)  
  
# 동적 배치  
dynamic_shapes = {"x": {0: Dim("batch")}}  
  
# 파이토치 내보내기  
exported_program = export(pt2e_model, inputs, dynamic_shapes= dynamic_shapes)  
  
# export 된 모델을 백엔드 설정과 함께 executorch로 변환  
executorch_program = to_edge_transform_and_lower(  
    exported_program,  
    partitioner = [XnnpackPartitioner()]  
).to_executorch()  
  
# pte 파일로 저장  
with open(f'{m_path}/{name}_pt2e.pte', "wb") as file:  
    file.write(executorch_program.buffer)
```

#### 정적 양자화  
  
`quantize_static` 함수와 `CalibrationDataReader`을 구축하여 활성화까지 정적 양자화 가능합니다.

```python
import onnx  
import onnxruntime  
from onnxruntime.quantization import quantize_static, QuantType  
import os  
import numpy as np  
import torch  
  
# Calibration Data Reader 클래스 정의  
class DataReader(onnxruntime.quantization.CalibrationDataReader):  
    def __init__(self, data_loader):  
        self.data_loader = data_loader  
        self.enum_data_loader = iter(data_loader)  
  
    def get_next(self):  
        try:  
            # ONNX Runtime은 NumPy 배열을 입력으로 받습니다.  
            images, labels = next(self.enum_data_loader)  
            input_feed = {"x": images.numpy()}  
            return input_feed  
        except StopIteration:  
            return None  
  
# 이전에 저장한 FLOAT 타입 ONNX 모델 경로  
onnx_model_path = f'{m_path}/torch_flower.onnx'  
  
# 양자화된 모델을 저장할 경로  
quantized_model_path_static = f'{m_path}/{name}_sq.onnx'  
  
# Calibration Data Reader 인스턴스 생성  
data_reader = DataReader(val_loader)  
  
  
# 정적 양자화 수행  
quantize_static(  
    onnx_model_path,  
    quantized_model_path_static,  
    data_reader,  # CalibrationDataReader  
    weight_type=QuantType.QInt8, # 가중치를 INT8로 양자화  
    activation_type=QuantType.QInt8 # 활성화를 INT8로 양자화  
)  
  
print(f"Statically quantized model saved to: {quantized_model_path_static}")  
  
# 양자화된 모델 파일 크기 확인 (선택 사항)  
print(f"Original model size: {os.path.getsize(onnx_model_path)/1e6:.4f} MB")  
print(f"Statically quantized model size: {os.path.getsize(quantized_model_path_static)/1e6:.4f} MB")  
  
# 저장된 정적 양자화 모델의 가중치 타입 확인  
onnx_model_static = onnx.load(quantized_model_path_static)  
graph_static = onnx_model_static.graph  
  
for initializer in graph_static.initializer:  
    print(f"Name: {initializer.name}, Data Type: {onnx.TensorProto.DataType.Name(initializer.data_type)}")
```
> ONNX 양자화는 모바일넷 같은 복잡한 구조((ReLU6, depthwise conv)를 가진 모델에서 성능저하가 크다


### ONNX 모델을 TensorRT로  
  
tensorrt 라이브러리를 활용하여 onnx로부터 그래프를 파싱하는 방식으로 onnx -> tensorrt 변환이 가능합니다.  
  
이때 컴퓨터 환경의 CUDA 버전에 맞게 tensorrt를 설치해야 하며, 다음 경로구성과 같이 onnx 파일의 부모 경로에 onnx.data 파일이 구성되어야 합니다.  
  
**ONNX 경로 구성**  
  
    current-working-directory    
    ├── model    
    │   └── model.onnx    
    └── model.onnx.data

`!pip install tensorrt-cu12`

```python
import tensorrt as trt  
import os  
  
m_path = 'model'  
name = 'torch_flower'  
  
onnx_file_path=f'{m_path}/{name}.onnx'  
engine_file_path=f'{m_path}/{name}.plan'  
  
# 로거 생성 (TensorRT 메시지 출력)  
TRT_LOGGER = trt.Logger(trt.Logger.VERBOSE)  
# 명시적 배치 설정  
EXPLICIT_BATCH = 1 << (int)(trt.NetworkDefinitionCreationFlag.EXPLICIT_BATCH)  
  
# 빌더 및 네트워크 생성  
builder = trt.Builder(TRT_LOGGER)  
network = builder.create_network(EXPLICIT_BATCH)  
  
# 빌더 config 생성  
config = builder.create_builder_config()  
  
# 워크스페이스 메모리 설정 (GPU 메모리 사용량 제한)  
max_workspace_size_gb = 16  
config.set_memory_pool_limit(trt.MemoryPoolType.WORKSPACE, max_workspace_size_gb * (1 << 30))  
  
# FP16 경량화 가능  
config.set_flag(trt.BuilderFlag.FP16)  
  
# ONNX 파서 생성  
parser = trt.OnnxParser(network, TRT_LOGGER)  
  
# 모델 파싱  
print(f"🔨 ONNX 파일 로드 및 파싱 시작: {onnx_file_path}")  
with open(onnx_file_path, 'rb') as model:  
    if not parser.parse(model.read()):  
        print("❌ ONNX 파싱 오류:")  
        for error in range(parser.num_errors):  
            print(parser.get_error(error))  
  
print("✅ ONNX 파싱 완료.")  
  
# 동적 배치 설정  
profile = builder.create_optimization_profile()  
  
# 입력 텐서의 최소, 최적, 최대 크기 정의  
min_shape = (1, 3, 224, 224)  
opt_shape = (1, 3, 224, 224)  
max_shape = (3, 3, 224, 224)  
  
# set_shape(입력 이름, 최소 크기, 최적 크기, 최대 크기)  
profile.set_shape(  
    'x',  
    min_shape,  
    opt_shape,  
    max_shape  
)  
  
# 설정된 프로파일을 빌더 config에 추가  
config.add_optimization_profile(profile)  
  
# 최종 엔진 구축 및 컴파일  
print("TensorRT 엔진 구축 및 최적화 시작...")  
serialized_engine = builder.build_serialized_network(network, config)  
  
if serialized_engine is None:  
    print("엔진 구축 실패.")  
else:  
    # 엔진을 파일로 저장 (바이트 직렬화)  
    print(f"엔진 직렬화 및 저장: {engine_file_path}")  
    with open(engine_file_path, "wb") as f:  
        f.write(serialized_engine)
```
