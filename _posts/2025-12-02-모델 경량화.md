# 1. 모델 경량화 전략

## 모델 경량화의 필요성

### 자원 제약적 환경에 배포
- **기존 모델 실행환경**
	- 기존 모델의 배포환경은 클라우드 컴퓨팅 방식
	- 고사양 중앙컴퓨터는 큰 모델 서빙에 문제 없음
- **엣지 및 모바일 기기**
	- 스마트폰, IoT장치 등 제한된 메모리, 처리 능력, 전력을 가지는 환경에서도 모델 배포의 요구가 많아짐
	- 자원이 제약된 상황에서는 기존의 큰 모델의 실시간 작동 어려움
	- 경량화를 통해 제약된 환경에서 모델 서빙
- **임베디드 시스템**
	- 로봇, 자율 주행과 같은 임베디드 시스템은 공간 젝약으로 일반적인 서버 PC에 비해 자원 제약적 환경
	- 모델 경량화를 통해 독립적이고 통신에 비의존적인 모델 활용 전략 수립

### 추론 지연 시간(Latency) 감소
- **실시간 서비스**
	- 음성 인식, 얼굴 인식, 실시간 번역과 같이 즉각적인 응답이 요구되는 서비스에서 모델의 **추론 속도**는 매우 중요
	- 경량화는 연산량을 줄여 지연 시간을 최소화
- **사용자 경험 개선**
	- 웹이나 앱 서비스에서 추론 시간이 짧아지면 사용자 경험도 같이 개선됨.
### 운영 비용 절감
- 서버 비용
	- 클라우드 서버에서 모델 운용 시 모델의 크기가 크고 복잡하면, 더많은 컴퓨팅 자원을 요구 ➡️ 운영 비용증가
- **전력 효율**
    - 데이터 센터의 서버들은 막대한 전력을 소비
    - 모델을 경량화를 통해 연산에 필요한 전력 소모를 줄여 에너지 효율을 개선

### **모델 배포 및 관리의 용이성**

- **저장 공간**
    - 대규모 모델은 수백 MB에서 수 GB에 이르어 배포를 위한 메모리 확보가 어려움
    - 경량화는 모델 파일의 크기를 줄여 저장 및 배포를 용이하게 함
- **버전 관리**
    - 모델 크기가 작아지면 재학습을 통한 업데이트 및 버전 관리가 더 수월해짐

## 모델 경량화 종류

### 대표 모델 경량화 방식

- **Distillation (증류)**
    - 큰 모델(Teacher Model)이 학습한 지식을 작은 모델(Student Model)에게 전달하는 방식.
- **Pruning (가지치기)**
    - 불필요한 가중치나 뉴런을 식별하고 제거하여 모델을 희소(sparse)하게 만드는 방식
- **Quantization (양자화)**
    - 기존 모델 학습시 활용한 가중치의 타입을 더 작은 비트로 표현가능한 타입으로 변환하여 모델의 크기를 줄이고 연산 속도를 높이는 방식

### **Knowledge Distillation**(증류)

Knowledge Distillation: A Survey

- **핵심 개념**
    - 큰 모델(Teacher)의 지식(softmax 확률 분포·중간 표현)을 작은 모델(Student)이 모사하여, 파라미터 수는 줄이면서 일반화 성능을 최대한 유지
- **주요 유형**
    - Logit Distillation: 최종 로짓/확률 분포만 모사(가장 보편적).
    - Feature/Hint Distillation: 중간 레이어 특징을 지도(ResNet stage, Transformer block 등).
    - Attention/Relation Distillation: 어텐션 맵, 샘플 간 관계(상관/순위)까지 모사.
    - Self-/Born-Again Distillation: 동일 구조를 teacher로 삼아 반복 증류.
    - Multi-Teacher: 여러 teacher의 지식 앙상블을 student에 집약.
- **기본 절차**
    1. Teacher 고정(또는 함께 미세 조정)
    2. Student 초기화(작은 폭/깊이, 경량 블록)
    3. 증류 손실로 훈련(하이퍼: α,τ\alpha, \tauα,τ, 학습률 등 탐색)
    4. 학생 모델의 결과와 실제 라벨 간의 Cross-Entropy 손실(하드 라벨) + 학생 모델의 예측과 교사 모델의 소프트 레이블 간의 손실(소프트 라벨)을 함께 사용
- **장단점·주의점**
    - 장점: 작은 모델로 성능 유지가 잘 됨. 라벨 노이즈에 강해지는 경향.
    - 주의: Teacher가 과도하게 편향되면 편향 전이. 중간표현 증류는 구현·메모리 부담.
- **활용 용도**
    - 베이스 모델이 크고 강력할 때, 성능 저하 최소화가 최우선일 때.
    - Pruning/Quantization 전 사전 성능 방어용으로 병행하면 효과적.

### Pruning (가지치기)


Learning both Weights and Connections for Efficient Neural Networks

- **핵심 개념**
    - 기여도가 낮은 가중치/채널/블록을 제거해 희소화하거나 구조를 얇게 만들어 연산량(FLOPs)과 파라미터를 줄인다.
- **주요 유형**
    - **비구조적(Unstructured) 가지치기**
        - 모델의 가중치 행렬에서 개별 가중치를 제거
        - 모델 압축률이 매우 높아져 높은 희소성을 달성할 수 있습니다.
        - 가중치가 불규칙하게 제거되기 때문에 연산 효율이 떨어질 수 있음
        - ex) 가중치의 절대값(L1)이나 제곱(L2)이 작을수록 중요도가 낮다고 판단
    - **구조적(Structured) 가지치기**
        - 가중치 그룹(필터/채널/헤드/블록)을 제거하는 방식
        - 규칙적인 구조를 제거하기 때문에 추론 속도 향상이 높음
        - 비구조적 가지치기보다 압축률이 낮을 수 있으며, 성능 손실이 더 클 수 있음
        - ex) N:M 희소성 → 특정 그룹(M개의 가중치) 내에서 N개의 가중치만 남기고 나머지는 제거
- **기본 절차**
    1. 가지치기 기준 선택 후 가지치기 진행
    2. 가지치기 이후 추가 미세조정 진행
    3. 한 번에 많이 자르지 말고 점진적으로 가지치기→ 미세조정 반복
- **장단점·주의점**
    - 장점: 파라미터와 연산량이 직접적으로 감소하여 메모리 사용량을 확실하게 축소.
    - 주의: 가지치기 방식에 따라 장단점이 나뉘며 레이어 불균형 가능성 존재
- **활용 용도**
    - 실측 지연시간 감소가 목표(엣지·모바일) → 구조적 가지치기 선호
    - 메모리 한계가 심각하고 희소 커널 지원이 있을 때 → 비구조적도 유효

### Quantization (양자화)

- **핵심 개념**
    - FP32 데이터 타입을 가지는 가중치·활성값을 저정밀도(예: INT8/INT4/FP16/BF16)로 표현해 모델 크기↓, 메모리 대역폭↓, 연산 속도↑를 얻음
- **양자화 기본 공식**
    - 양자화: $q=round(clip(x/scale))+z_p)$
    - 스케일 팩터(Scale Factor, $scale$): 부동소수점 값의 범위를 정수 값의 범위에 맞추는 비율
    - 제로 포인트(Zero Point, $z_p$): 부동소수점 0이 정수 값 어디에 위치해야 하는지 결정
        - 비대칭적인 값 분포를 처리하기 위해 사용
    - 클리핑($clip$): 스케일 팩터와 제로 포인트를 계산하기 전에 값의 임계 범위를 설정
- **주요 유형**
    - **Post-Training Quantization(PTQ)**
        - 모델 학습을 완료한 후 양자화를 적용하는 방식
        - **Dynamic**: 가중치는 사전에 정수화 / 활성화 값은 추론 시점에 동적으로 양자화
        - **Static**: 가중치와 활성화 값 모두 사전에 정수화
    - **Quantization-Aware Training(QAT)**:
        - 모델 학습 과정에 양자화 효과를 시뮬레이션
        - 학습 과정에 가중치와 활성화 값에 _가짜 양자화(fake quantization)_ 연산을 삽입
        - 가짜 양자화 과정에서 얻은 오차에 적응하면 학습하여 양자화 성능 보존을 끌어올림
- **기본 절차**
    1. 타겟 백엔드(TFLite/ONNX Runtime/TensorRT 등) 결정
    2. 양자화 데이터 타입 선택(INT8 우선, 필요 시 16bit)
    3. PTQ로 빠르게 가늠 → 정확도 손실 크면 QAT로 전환
    4. 배포 하드웨어에서 지연시간/스루풋(처리율)/전력 효율 등 검증
- **장단점·주의점**
    - 장점: 크기·지연시간·전력 동시 개선의 가성비 최고.
    - 주의: 대표 데이터가 실제 분포와 달라지면 정확도 급락(특히 PTQ-Static).
- 활용 용도
    - 마이크로컨트롤러/모바일/엣지 등 자원 제약이 큰 환경의 1순위.
    - CNN/비전은 INT8 PTQ만으로도 성능 유지가 좋은 편
    - LLM/Transformer는 4~8bit + 추가 최적화 방식(GPTQ/AWQ/QLoRA 등) 고려.

### 함께 쓰기(조합 전략)

- **증류 → 양자화(QAT/PTQ)**: 작은 student를 먼저 만들고 정밀도 낮추면 정확도 손실 최소화.
- **가지치기 → 증류**: 강한 가지치기 이후 리커버리 증류로 성능 회복.
- **가지치기 + 양자화**: 구조를 줄이고 정밀도까지 낮추면 지연시간/전력을 크게 줄임.
