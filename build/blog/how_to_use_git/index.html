Git이란?

Git은 분산 버전 관리 시스템(Version Control System)입니다.

Git을 사용하는 이유

  • 코드 변경 이력 추적
  • 여러 사람과 협업 가능
  • 실수해도 이전 버전으로 복구 가능
  • 여러 기능을 동시에 개발 가능 (브랜치)

Git 기본 개념

저장소 (Repository)

  • 로컬 저장소: 내 컴퓨터에 있는 Git 저장소
  • 원격 저장소: GitHub, GitLab 등에 있는 온라인 저장소

작업 영역

Working Directory (작업 디렉토리)
    ↓ git add
Staging Area (스테이징 영역)
    ↓ git commit
Local Repository (로컬 저장소)
    ↓ git push
Remote Repository (원격 저장소)

주요 용어

  • commit: 변경사항을 저장소에 기록
  • push: 로컬 저장소의 변경사항을 원격 저장소로 업로드
  • pull: 원격 저장소의 변경사항을 로컬로 다운로드
  • clone: 원격 저장소를 로컬로 복제
  • branch: 독립적인 작업 공간
  • merge: 브랜치를 합치기

Git 설치 및 초기 설정

설치 확인

git --version

사용자 정보 설정

# 이름 설정
git config --global user.name "Your Name"

# 이메일 설정
git config --global user.email "your.email@example.com"

# 설정 확인
git config --list

기본 에디터 설정 (선택사항)

git config --global core.editor "code"  # VS Code
git config --global core.editor "vim"   # Vim

Git 기본 명령어

저장소 생성 및 복제

새 저장소 생성

git init
  • 현재 디렉토리를 Git 저장소로 초기화

원격 저장소 복제

git clone <repository-URL>
  • 원격 저장소를 로컬로 복제

기본 작업 명령어

상태 확인

git status
  • 현재 작업 상태 확인 (변경된 파일, 스테이징된 파일 등)

변경사항 추가 (스테이징)

git add <파일명>          # 특정 파일만 추가
git add .                # 모든 변경사항 추가
git add *.js             # 특정 확장자 파일만 추가

커밋

git commit -m "커밋 메시지"
  • 스테이징된 변경사항을 로컬 저장소에 기록

커밋 이력 확인

git log                  # 전체 로그
git log --oneline        # 한 줄로 간단히
git log --graph          # 그래프 형태로

원격 저장소 연결

git remote add origin <repository-URL>
git remote -v            # 연결된 원격 저장소 확인

푸시 (업로드)

git push origin main     # main 브랜치에 푸시
git push                 # 기본 브랜치에 푸시

풀 (다운로드)

git pull                 # 원격 저장소의 변경사항 가져오기
git pull origin main     # 특정 브랜치에서 가져오기

Git 워크플로우

1. 프로젝트 시작하기

방법 A: 새 프로젝트 시작

# 1. 프로젝트 폴더 생성
mkdir my-project
cd my-project

# 2. Git 저장소 초기화
git init

# 3. 파일 생성 및 작업
echo "# My Project" > README.md

# 4. 변경사항 추가 및 커밋
git add .
git commit -m "Initial commit"

# 5. 원격 저장소 연결 (GitHub에서 먼저 생성)
git remote add origin https://github.com/username/my-project.git

# 6. 푸시
git push -u origin main

방법 B: 기존 프로젝트 복제

git clone https://github.com/username/project.git
cd project

2. 일반적인 작업 흐름

# 1. 최신 코드 가져오기
git pull

# 2. 파일 수정 작업

# 3. 변경사항 확인
git status

# 4. 변경사항 스테이징
git add .

# 5. 커밋
git commit -m "기능 추가: 로그인 페이지"

# 6. 원격 저장소에 푸시
git push

3. 협업 시 워크플로우

# 작업 시작 전
git pull                 # 최신 코드 받아오기

# 작업 수행
# ... 코드 수정 ...

# 커밋 및 푸시
git add .
git commit -m "변경사항 설명"
git push

브랜치 관리

브랜치란?

독립적인 작업 공간으로, 새로운 기능을 개발하거나 버그를 수정할 때 사용합니다.

브랜치 기본 명령어

# 브랜치 목록 확인
git branch

# 새 브랜치 생성
git branch feature/login

# 브랜치 이동
git checkout feature/login

# 브랜치 생성 + 이동 (한번에)
git checkout -b feature/login

# 최신 Git에서는 switch 사용 권장
git switch feature/login
git switch -c feature/new-feature

브랜치 작업 흐름

# 1. 새 기능 브랜치 생성
git checkout -b feature/user-profile

# 2. 작업 수행 및 커밋
git add .
git commit -m "사용자 프로필 페이지 추가"

# 3. 원격에 브랜치 푸시
git push -u origin feature/user-profile

# 4. main 브랜치로 이동
git checkout main

# 5. 브랜치 병합
git merge feature/user-profile

# 6. 원격에 병합 결과 푸시
git push

# 7. 브랜치 삭제 (선택사항)
git branch -d feature/user-profile
git push origin --delete feature/user-profile

충돌 해결

충돌이 발생하는 경우

  • 같은 파일의 같은 부분을 여러 사람이 수정했을 때
  • 내가 수정한 파일을 다른 사람도 수정해서 푸시했을 때

충돌 해결 과정

시나리오: 내가 수정 중인데 원격에도 변경사항이 있는 경우

# 1. 현재 작업 임시 저장
git stash
# 또는
git stash save "작업 중인 내용"

# 2. 원격 변경사항 가져오기
git pull
# 또는 (rebase 사용 시)
git pull --rebase

# 3. 임시 저장한 작업 다시 적용
git stash pop

# 4. 충돌 발생 시 - 충돌 파일 확인
git status

# 5. 충돌 파일 수동 수정
# 에디터에서 다음과 같은 마커를 찾아 수정
# <<<<<<< HEAD
# 현재 브랜치의 내용
# =======
# 가져온 브랜치의 내용
# >>>>>>> branch-name

# 6. 충돌 해결 후 스테이징
git add .

# 7. 커밋
git commit -m "충돌 해결"
# rebase 사용 시
git rebase --continue

# 8. 푸시
git push

충돌 해결 팁

# 충돌 파일 목록 확인
git diff --name-only --diff-filter=U

# 충돌 내용 상세 확인
git diff

# 충돌 해결 중 취소하고 싶을 때
git merge --abort      # merge 취소
git rebase --abort     # rebase 취소

# stash 목록 확인
git stash list

# 특정 stash 적용
git stash apply stash@{0}

# stash 삭제
git stash drop
git stash clear        # 모든 stash 삭제

유용한 팁

자주 사용하는 명령어

# 마지막 커밋 메시지 수정
git commit --amend -m "새로운 커밋 메시지"

# 파일을 스테이징에서 제거 (작업 내용은 유지)
git reset HEAD <파일명>

# 특정 파일의 변경사항 취소
git checkout -- <파일명>

# 마지막 커밋 취소 (작업 내용은 유지)
git reset --soft HEAD~1

# 마지막 커밋 취소 (작업 내용도 삭제)
git reset --hard HEAD~1

# 특정 커밋으로 되돌리기
git reset --hard <커밋해시>

# 원격 브랜치 목록 확인
git branch -r

# 모든 브랜치 확인 (로컬 + 원격)
git branch -a

.gitignore 파일

특정 파일이나 폴더를 Git에서 무시하도록 설정

# .gitignore 파일 생성
touch .gitignore

.gitignore 예시

# 의존성 폴더
node_modules/
venv/

# 환경 변수 파일
.env
.env.local

# 빌드 결과물
dist/
build/
*.log

# IDE 설정
.vscode/
.idea/

# OS 파일
.DS_Store
Thumbs.db

커밋 메시지 컨벤션

# 기능 추가
git commit -m "feat: 로그인 기능 추가"

# 버그 수정
git commit -m "fix: 로그인 버튼 클릭 안되는 버그 수정"

# 문서 수정
git commit -m "docs: README 파일 업데이트"

# 스타일 변경
git commit -m "style: 코드 포맷팅 적용"

# 리팩토링
git commit -m "refactor: 사용자 인증 로직 개선"

# 테스트 추가
git commit -m "test: 로그인 기능 테스트 추가"

유용한 별칭 (Alias) 설정

# 자주 사용하는 명령어를 짧게 설정
git config --global alias.co checkout
git config --global alias.br branch
git config --global alias.ci commit
git config --global alias.st status
git config --global alias.lg "log --oneline --graph --all"

# 사용 예시
git co main         # git checkout main
git st              # git status
git lg              # git log --oneline --graph --all

문제 해결

push가 거부될 때

# 원인: 원격 저장소에 새로운 커밋이 있음
# 해결:
git pull --rebase
git push

실수로 커밋한 파일 제거

# 파일 삭제하고 커밋
git rm <파일명>
git commit -m "불필요한 파일 삭제"
git push

# 파일은 유지하고 Git에서만 제거
git rm --cached <파일명>
git commit -m "Git 추적에서 제거"
git push

원격 브랜치와 동기화

# 원격에서 삭제된 브랜치를 로컬에서도 제거
git fetch --prune

# 원격 브랜치 최신 정보 가져오기
git fetch

요약 치트시트

명령어 설명
git init 저장소 초기화
git clone <URL> 저장소 복제
git status 상태 확인
git add . 모든 변경사항 스테이징
git commit -m "메시지" 커밋
git push 원격에 푸시
git pull 원격에서 풀
git branch 브랜치 목록
git checkout -b <브랜치명> 브랜치 생성 및 이동
git merge <브랜치명> 브랜치 병합
git stash 작업 임시 저장
git stash pop 임시 저장 복원
git log 커밋 이력
